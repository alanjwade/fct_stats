# FCT Stats — Data Paradigm & Migration Plan

## Core Concepts

| Term | Meaning |
|------|---------|
| **Source** | Original raw data: spreadsheets (.ods), markdown docs, cached HTML. Never modified by code. |
| **Parse** | Transform a source into standardized JSON. One-time for frozen years; repeated for live year. |
| **Snapshot** | The parsed JSON files under `data/snapshots/`. Intermediate layer; re-creatable from sources. |
| **Ingest** | Load snapshots into `fct_stats.db`. Fast, no network required. |
| **Rebuild** | Delete the DB (or a year-slice of it) and re-ingest from snapshots. |
| **Frozen** | Historical + prior-year data. Snapshots are checked in and treated as immutable. Never re-parsed unless a bug is found. Parse step should require `--force` to overwrite. |
| **Live** | Current-year (2026) data. Re-parsed and re-ingested frequently. |

## Target Directory Layout

```
data/
├── sources/                        ← raw inputs, never generated by code
│   ├── historic/                   ← school records markdown (frozen)
│   │   ├── FCHS Boys Track & Field Records.docx.md
│   │   └── FCHS Girls Track & Field Records.docx.md
│   ├── 2025/                       ← 2025 ODS spreadsheet (frozen, final version only)
│   │   └── 2025 Track & Field Performance List 3.xlsx.ods
│   └── 2026/                       ← current year cached pages (live)
│       └── pages/
│           └── *.json / *.txt      ← cached MileSplit pages (optional)
│
├── snapshots/                      ← parsed JSON, the canonical intermediate layer
│   ├── historic/
│   │   └── historical_records.json ← ONE copy, frozen; produced by parse_historical_records.py
│   ├── 2025/
│   │   └── meets/
│   │       └── *.json              ← per-meet JSONs, frozen
│   └── 2026/
│       └── gsheet_2026.json        ← re-created from Google Sheet (live)
│
├── db/
│   └── fct_stats.db                ← built entirely from snapshots
│
└── analytics/
    └── analytics.db                ← webapp page-view tracker, independent
```

**Config** (`config/`) stays as-is for event/school/name normalization files:
- `canonical_events.yaml`, `meet_names.yaml`, `schools.yaml` — unchanged
- `meets_2025.json`, `meets_2026.json` — **single canonical location here**; scripts all read from `config/`, no duplicate copies in `data/sources/`

## Workflows

### 1. Full rebuild — rare (new machine, schema change, bulk correction)
```
python manage_data.py rebuild-all
```
1. Wipe `fct_stats.db`
2. Ingest `snapshots/historic/historical_records.json`
3. Ingest `snapshots/2025/meets/*.json`
4. Parse Google Sheet → `snapshots/2026/gsheet_2026.json`  *(or skip fetch, use existing)*
5. Ingest `snapshots/2026/gsheet_2026.json`

### 2. Refresh current year — common (new meet, correction in sheet)
```
python manage_data.py refresh-2026
```
1. Wipe 2026 data from DB: `DELETE FROM results WHERE meet IN (SELECT id FROM meets WHERE season='2026')`  *(+ cascades)*
2. Re-fetch & parse Google Sheet → `snapshots/2026/gsheet_2026.json`
3. Ingest `snapshots/2026/gsheet_2026.json`

### 3. Ingest-only — fast (no network, no parsing; e.g., after schema tweak)
```
python manage_data.py ingest-2026
```
1. Wipe 2026 data from DB
2. Ingest existing `snapshots/2026/gsheet_2026.json`

### 4. Re-parse frozen year — exceptional (found bug in 2025 data)
```
python manage_data.py reparse-frozen 2025 --force
```
1. Re-parse source → `snapshots/2025/meets/`
2. Follow with `rebuild-all` to get a clean DB

## Key Principles

1. **One source of truth per year.** 2025 = ODS spreadsheet (frozen). 2026 = Google Sheet (live). Historical = markdown docs.
2. **Snapshots are the contract.** All ingest scripts read from `snapshots/`. Parsers write to `snapshots/`. The DB is always 100% rebuildable.
3. **Year-scoped DB wipe.** The `meets` table needs a `season` column (or derive from date) so a single year can be wiped without touching others.
4. **Single meets config location.** `config/meets_<year>.json` is canonical. No copies in `data/sources/`. Scripts read from `config/`.
5. **Frozen means committed.** 2025 and historical snapshots are checked into git. Parse step warns/requires `--force` to overwrite.
6. **One command per workflow.** `manage_data.py` (new) replaces the current loose collection of scripts.
